# GravitySouls 当前功能与部署说明

本文按当前代码、项目配置和已有线上验收记录说明产品功能及运行方式。仓库实现状态与线上环境状态分开描述；线上环境的密钥、实际数据库内容和当前部署提交无法从代码仓库确认。

## 产品概览

GravitySouls 是一个以星球代表用户个人资料、以星系呈现社区、以 Resonance 提供匹配探索的社交应用。主要页面采用英语、法语和中文。用户可以先浏览公开介绍，再注册、创建星球并参与社区、内容和私信互动。

核心对象关系如下：

- **Planet（星球）**：用户当前使用的个人形象和资料。星球可自定义外观；重新校准时保留一个当前激活的星球。
- **Galaxy（星系）**：Community（社区）的展示形式，不是另一套独立社区数据。社区成员、帖子、讨论和活动均沿用 Community 关联。
- **Signal（信号）**：全站 Post，或社区中的 CommunityPost / CommunityDiscussion。
- **Resonance（共鸣）**：可选的用户匹配推荐，也是进入星球探索和后续社交互动的入口。
- **Relationship（关系）**：单向关注、私有收藏、屏蔽以及建立在双方许可上的私信关系。

18 岁以上为注册门槛。出生日期（如用户提供）属于私人资料，不进入公开星球信息或匹配评分；年龄和性别标签只有在用户分别开启公开选项后才会显示。出生日期与成年声明用于自我声明，不代表证件或身份核验。

## 用户功能链路

### 1. 公开访问、注册与账号

1. 访问首页、`/cosmic-globe`、`/guide` 和法律信息页面，浏览产品介绍、使用指南及服务条款、隐私和社区准则草案。
2. 通过邮箱密码注册/登录，或使用 Google、Apple 社交登录。
3. 注册时完成 18+ 声明及适用的政策确认；支持邮箱验证与密码重置（邮件服务配置后发送）。
4. 新账号完成私密基础资料与偏好设置，再进入星球校准。部分问题可以跳过或清空；注册前的匿名校准草稿可继续使用。
5. 在账号、基本资料和星球设置中管理语言、密码、邮箱验证、基础资料、连接偏好、星球设置及公开标签。
6. 用户可以导出个人数据，也可使用账号删除流程。个人设置和注册资料不会默认作为公开资料返回。

### 2. 创建、查看和定制星球

1. 校准问卷收集用于匹配和星球生成的回答；匹配校准是可选流程。
2. 校准完成后生成用户星球，可编辑名称、描述、外观和纹理。
3. 星球详情展示当前允许访问的资料与公开标签，并提供关注、收藏、光束/会话入口和举报等操作。
4. 用户可在个人星球、编辑页、详情页和地图之间跳转。只有启用公开选项的年龄/性别信息才会出现在公开星球展示中。

### 3. 探索、搜索与 Resonance

1. 首页、Discover、搜索和星图提供星球、星系及活动的探索入口。
2. 星图支持发现、星系和个人关系视图；可以按气候/筛选条件浏览真实星球或社区节点、搜索并分页加载。地图上的装饰粒子和连线只用于视觉引导，不代表真实关系或消息发送。
3. Resonance 以列表或星图展示至多五个匹配推荐，并提供匹配程度、覆盖情况和推荐理由。未回答的偏好不计分；私人问卷答案不会作为他人可读取资料返回。
4. 选择地图节点或搜索结果后进入真实星球/星系详情，再由详情页执行关注、收藏、加入或私信等操作。
5. 个人星图汇集本人保存、关注、互关、社区和活动等可见关系；“已保存”是私有收藏，不会通知被收藏者。

### 4. 关注、收藏、屏蔽与举报

- 关注是单向关系；可查看关注/粉丝/互关状态，并在关系页维护关注。
- 星球收藏可添加或移除，在个人保存列表和个人地图中查看。
- 屏蔽会限制双方的资料访问和新联系；资料可见性、社区权限及屏蔽检查由服务端统一执行。
- 用户可以举报资料、内容或相关对象；管理员有独立的举报管理页面。
- 私密资料、已屏蔽用户、非成员社区内容等不会因为推荐、地图节点或通知链接而绕过访问授权。

### 5. 全站内容流

1. 用户在 Stream/帖子页面浏览真实全站 Post，并打开帖子详情。
2. 登录用户可以发布文字内容及适用媒体、添加社区/活动上下文，编辑或删除自己的全站帖子。
3. 用户可以点赞、评论和回复评论；列表、详情及关联内容在成功写入后同步更新。
4. 关注、评论、回复及内容相关活动可形成站内通知；读取和分页不会通过读取接口隐式修改用户状态。

### 6. 星系（社区）、讨论与活动

1. 用户浏览、筛选星系或创建星系。创建者成为 Owner 和首位管理员。
2. 加入策略可以是开放加入或管理员审批；用户可提交、撤回加入申请、离开社区。管理页面用于编辑社区资料、成员策略、审核申请和管理成员；管理员任命及所有权转移由 Owner/平台操作员控制。
3. 成员可以发布社区帖子、发起讨论、回复以及对回复点赞。帖子和讨论在服务端校验社区成员身份；作者名使用公开化名。作者或社区管理员可删除帖子/讨论，作者可以删除自己的回复；社区帖子和讨论目前没有编辑入口。
4. 社区成员浏览活动并提交活动提案；提案须经 Owner/管理员审核。活动支持编辑、重新提交、取消和审核。
5. 成员可以表达有兴趣、报名或申请参加、撤回参与；活动可配置直接确认或组织者审批，并遵守活动状态和名额限制。社区活动页及 `/activities` 汇总活动、个人兴趣和参与状态，并提供活动日历入口。
6. 社区内容按成员资格和资料可见性返回；非成员不会因为公开星系目录而获得完整成员名册或受限内容。

### 7. 私信与光束邀请

1. 双方互相关注时，可以打开或创建对话；打开对话本身不会发送消息。现存对话即使关注关系后来变化仍可继续使用，但屏蔽等权限限制仍生效。
2. 非互关用户可以发送无附言的光束邀请；接收者可接受或拒绝，发送者可取消。接受仅创建/复用空对话，不会自动关注、发送消息或产生奖励。
3. 对话支持分页历史、文字消息、私密图片、星球/星系/活动分享卡片、引用回复、表情回应、已读状态和未读计数。消息发送支持客户端幂等标识；失败时保留草稿并显示错误。
4. 分享卡片和引用在读取时重新检查当前权限，不保存目标内容快照；无权访问或已失效的目标不会展示受限细节。
5. 站内消息通知与普通通知分别维护。设置中可主动启用 Web Push；推送载荷不包含消息正文、图片或分享内容，名称展示需再通过服务端鉴权。

### 8. 通知、活动记录与管理

- 通知中心支持分页、单条/批量已读和内部页面深链；消息未读与普通通知的未读状态相互独立。
- 站内通知覆盖关注、互动、社区、活动、邀请、等级和消息等已接入场景，并按接收者语言生成新通知。
- 活动页和个人地图展示与用户相关的活动、社区和关系入口。
- 管理员举报页面提供平台举报处理入口；平台操作员由部署环境配置的邮箱名单识别。

## 当前实现边界

- 星系是社区的展示名；全站帖子与社区帖子/讨论是不同内容类型。
- 社区帖子、讨论本身没有编辑功能；全站帖子支持的编辑能力不等同于社区内容编辑。
- 年龄和性别公开标签是用户单独选择的；出生日期不会公开。18+ 检查是自我声明与日期校验，不是证件核验。
- Web Push 依赖部署环境配置 VAPID 密钥；未配置或不可用时不会请求浏览器通知权限或创建推送任务。
- 法律信息页面存在于应用中；项目记录将其视为尚待补全具体法务主体与联系信息的页面，不能据此推断法律审查或上线合规已经完成。

## 当前部署与运行方式

### 应用、构建与发布

- 应用为 Next.js 16 App Router、React 19、TypeScript 项目，目标域名在项目 README 中记为 `gravitysouls.com`。
- 仓库的 Vercel 配置设置生产构建命令为 `npm run build:deploy`。该命令先执行 `prisma migrate deploy`，随后执行 `npm run build`；后者生成 Prisma Client 并构建 Next.js 应用。
- 因此发布流程依赖部署环境先提供数据库连接和必要密钥，并要求数据库迁移成功；迁移失败时构建/发布不能完成。
- GitHub Actions 在 `main` 推送和 Pull Request 上执行 lint、类型检查、Prisma 校验、单元/集成测试、构建及浏览器测试。CI 是验证流水线，仓库中没有把 CI 工作流配置成直接部署生产环境。
- 本地主要命令为 `npm run dev` 和 `npm run start`；开发/测试数据库脚本对数据库 URL 有 loopback 与数据库名后缀限制，生产迁移使用 `prisma migrate deploy`。

### 数据库与文件存储

- 数据使用 PostgreSQL 和 Prisma 7；运行时通过 `DATABASE_URL` 连接。Prisma CLI 使用 `DIRECT_URL`，或使用 Vercel/Neon 集成提供的 `DATABASE_URL_UNPOOLED` 作为非池化迁移连接。
- 公开星球纹理、全站媒体和活动封面在生产环境通过 Vercel Blob 持久化。README 说明生产上传需要配置 `BLOB_READ_WRITE_TOKEN`。
- 私信图片采用私有 Blob 存储，使用独立的 `CHAT_PRIVATE_BLOB_TOKEN`；只有开发环境可用显式指定的本地目录，生产环境没有私有存储配置时会返回不可用。
- 项目还依赖 `AUTH_SECRET`、Better Auth URL、OAuth 提供方凭据等运行配置；可选邮件发送使用 Resend 配置。

### 定时任务与推送

- `vercel.json` 配置每天 UTC 03:00 调用 `/api/cron/chat-image-cleanup`，用于清理过期私信图片及相关过期任务；定时接口受 `CRON_SECRET` 保护。
- 代码另有 `/api/cron/push-delivery` 推送投递处理入口，但它没有列入当前 `vercel.json` 的 cron 调度。推送投递另需 `WEB_PUSH_PUBLIC_KEY`、`WEB_PUSH_PRIVATE_KEY`、`WEB_PUSH_SUBJECT` 等配置。
- Web Push 使用浏览器订阅与 Service Worker；启用由用户主动授权，账号/会话状态变化会撤销或限制订阅使用。
