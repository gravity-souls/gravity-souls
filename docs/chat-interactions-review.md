# 引用回复与消息回应：发布与验收

## 本轮完整链路

- 消息下点击回复 → 输入区显示引用 → 可取消，保留正文草稿 → 明确发送文字、图片或
  分享卡片 → 普通消息未读／站内通知 → 对方按当前权限查看引用。
- 点击引用 → 已加载的原消息滚动定位／短暂高亮；未加载的原消息通过鉴权 API 在
  对话框查看，不把孤立的旧消息窗口塞进分页历史。支持 Escape／关闭。引用预览和
  GET 不确认已读；实际显示的完整原消息仅通过现有 PATCH 确认那一条 incoming ID。
- 点击回应 → 六种表情之一 → 按用户显示当前选择／聚合数量 → 可替换或取消。
  每人每消息仅一个选择；失败可重试同一个意图，不重新计算一次 toggle。

本轮不包含撤回、删除／编辑消息、引用多条消息、置顶、任意文件、系统推送或外部
网址预览。这些仍需后续明确语义；没有新增消息保留或法律政策。

## 数据与权限

引用只存 nullable replyToId，验证源消息属于当前会话，不存名字、文字、标题或图片
快照。源被物理移除时仍可保留“原消息不可用”，不通过 FK 阻止后续删除。仅解析一层，
文字生成最多 160 个 Unicode code points 的 plain-text 摘要；图片／分享使用三语通用
标签，不在引用中曝光缩略图、附件读取 URL、共享目标 ID 或名称。共享目标按当前
查看者权限重新验证；不可用引用仅返回 available:false，不能点击或新选作回复。

文字、图片、分享的幂等键比较都包含 replyToId。确认已送达的匹配重试先返回既有
消息，再动态生成当前可见引用；源消失或变私密不会制造重复消息。更换正文或引用
属于新发送意图。发送在参与者／会话锁内重新验证账号有效和双向屏蔽，补强原文字
发送只在事务前检查权限的问题。可见原消息的已读确认也使用相同锁／当前权限。

回应 mutation 要求两个有效参与者和 canContact；可读的注销对方历史不允许新回应。
每消息每用户唯一，SQL 和 API 都限制六种 emoji。每小时 120 次实际变化，重复当前
期望状态不扣新额度。回应不创建消息、未读、通知、XP，也不更新 lastMessageAt。
返回聚合数量和自己的选择，不增加回应者身份字段。注销账号明确删除自己的回应，
消息／用户物理删除通过 FK cascade 清理辅助记录。

每次实际回应变化（含取消／注销账号）推进 reactionVersion。计数和版本从同一个
SQL snapshot 读取，客户端拒绝用低版本 polling 结果覆盖较新的确认状态，但仍接收
当前引用权限变化。版本不保证多个 tab 冲突意图的发起顺序，服务端提交顺序决定
结果。组件串行发送同消息的请求，断网后保留期望值供明确重试。

最新消息及已经加载的旧消息每 10 秒／前台复查，旧历史每批最多 100 个 ID，既包含
引用、分享也包含回应。返回遗漏的已加载源显示不可用；受限元数据复查失败时隐藏。
整体会话读取失败隐藏历史，避免继续展示失效授权的页面。不是实时撤销推送，也
无法让已收到信息的人忘记内容。原消息对话框同样复查；私密图片沿用 MR37 鉴权。

导出包含本人会话的标量引用及本人回应，不附加引用内容快照或额外回应者身份。

## 验证

190 项本地自动化测试通过：25 项新引用／回应真实数据库工作流、20 项聊天／三语
组件与版本状态、26 项私密图片、95 项原工作流及 24 项基础测试。真实迁移／Prisma／
路由／通知／XP／删除与导出执行在隔离 PGlite，仅认证替换；图片 suite 的外部 Blob
SDK 使用故障注入，不访问线上存储。包含老消息迁移兼容、越权引用、跨线程脏引用、
单层解析、图片／分享回复、target 私密／第三方屏蔽、失效后的已送达重试、键冲突、
回应聚合／替换／取消／限额、双向屏蔽、注销及无消息／未读／通知／XP／排序副作用。

生产构建、类型检查、Prisma 校验、变更 lint、三语键一致性通过。全仓 lint 没有错误，
16 项原有 warning。新测试已接入 CI；远端 CI 尚未确认通过。

新增 e2e/demo/chat-interactions.spec.ts 的 15 个场景只完成发现检查，覆盖三语引用选择／
重试、定位、回应响应丢失后重试和原消息对话框／单条已读／权限复查。旧分享历史
浏览器场景已改为通用 message-state 入口。当前环境没有可用浏览器引擎，未执行这些
场景；不宣称浏览器、真实手机/Safari或生产 PostgreSQL 并发验收完成。上线后仍需
双账号、键盘遮挡、真实私密图片引用与多端刷新验收。
