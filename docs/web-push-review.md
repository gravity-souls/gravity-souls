# 聊天系统推送与 MR47 验收

本轮与聊天草稿恢复一起合并。新文字、图片及站内分享卡片为收件人的已订阅设备创建投递任务；同一消息重试不会重复创建任务。回应、邀请和活动提醒保持现有站内通知。本轮不增加这些内容的系统推送。

## 部署配置

1. 在本地运行 `npx web-push generate-vapid-keys`，保存生成的密钥对。不要把私钥提交到 Git、聊天、截图或日志。
2. 在部署平台的 Production 环境增加 `WEB_PUSH_PUBLIC_KEY`、`WEB_PUSH_PRIVATE_KEY`、`WEB_PUSH_SUBJECT`。前两项分别使用生成的 Public Key 和 Private Key；Subject 使用真实联系邮箱的 `mailto:` 地址，例如 `mailto:admin@your-domain.com`。
3. 重新部署 main。现有 `npm run build:deploy` 会先执行 `prisma migrate deploy`；如果平台自行调用 build，需先运行同一数据库迁移命令。本轮新增 PushSubscription、PushDelivery 两张表及级联外键，不改变既有消息内容。
4. 在 HTTPS 网站的账号设置中主动开启系统通知。每个账号最多五个订阅设备，默认锁屏显示“你有一条新消息”，可主动选择显示发送者名称；始终不显示消息正文、图片或分享内容。

未配置或密钥无效时界面显示暂不可用，不申请通知权限，也不创建推送任务。密钥应稳定保存；轮换后各设备需关闭并重新开启通知。iPhone 需支持 Web Push 的系统版本，将网站添加到主屏幕后从该应用主动授权。桌面 Chrome、Firefox、Edge、Safari 及实际手机均需部署后验证；自动化 WebKit 不等同于 iPhone 操作系统推送验收。

## 投递和隐私边界

订阅绑定账号及登录会话，退出登录、会话删除、账号删除会级联撤销订阅和任务。浏览器退出前也尝试取消设备订阅并关闭可见通知；网络失败不阻止退出。切换账号不会接管另一个账号的订阅，需先关闭旧浏览器订阅再开启。

每次发送前重查会话有效期、双方屏蔽、删除状态、参与者和未读；加密推送载荷仅含投递 ID 与语言。服务工作线程显示名称前再次带当前登录凭据请求服务端鉴权，响应禁止缓存。该 worker 不拦截页面请求、不缓存聊天。订阅地址仅接受限定推送服务域名，禁止私网、任意服务器和带凭据地址。导出仅包含订阅元数据，不含 endpoint 或加密密钥。

Safari 要求已收到的推送必须显示可见通知。若消息已读、权限撤销、账号切换、离线或鉴权失败，worker 仅显示无账号／发送者／消息内容的通用提示并返回消息列表。已经交给推送服务或操作系统的通知无法保证撤回，因此不可宣称退出后绝无任何提示。

任务与消息在同一事务保存，消息响应后用 Next `after()` 处理，最多六个任务，单次网络超时五秒，推送服务 TTL 六十秒。暂时失败保留到下一次处理，间隔至少六十秒、最多三次，任务十五分钟过期；失效 endpoint 的 404/410 自动清除。租约及唯一约束避免并发重复提交，稳定通知 tag 合并同一聊天；网络接受后进程崩溃的极端情况仍可能重复，不能承诺操作系统恰好一次投递。

默认没有新增定时任务。下一次消息的后台处理会继续消费到期任务；最后一条消息遇到暂时故障时，若没有后续处理，可能过期。需要稳定自动重试时，可在支持相应频率的调度平台定期调用 `GET /api/cron/push-delivery`，请求头 `Authorization: Bearer <CRON_SECRET>`；不要把密钥放 URL。现有每日图片清理也清理过期任务，不负责及时重试。部署前按使用量确认平台函数时限和调度方案。

## 验证

真实迁移及 PGlite API 测试覆盖配置、主动订阅、账号／会话隔离、地址验证、锁屏偏好、消息幂等、已读／屏蔽／删除抑制、重试／租约、失效设备、取消及退出级联、cron 鉴权。worker 测试覆盖二次鉴权、不可缓存、失败通用提示及安全返回。三语浏览器用替代订阅对象检查未点击不申请、启用、锁屏偏好和取消；不会弹出实际操作系统授权。

部署后用两个测试账号验收：文字／图片／分享 → 收件设备后台提示 → 点击正确聊天 → 显式读取消息；取消订阅、双向屏蔽、退出／切换账号、权限拒绝、锁屏偏好、离线重试及真实 iPhone 主屏幕应用。此文不代表线上系统通知已经验收。
