# 产品链路完善与验收清单

记录日期：2026-10-04（巴黎时间）。本轮仅记录，不实施下列功能。

## 验收状态与原则

- 星系流程已提交 `05eb061`，通过本地回归、数据库流程、语言和构建检查；部署状态及线上多账号验收仍待确认。
- 下列链路均为待检查／待完善，不能因存在页面或接口就标为通过。
- 每项需记录实现状态、验收账号角色、步骤、预期／实际结果及证据。
- 验证桌面和手机、中英法、定制头像、刷新后的持久化、错误反馈及通知深链。

## 1. 动态与活动

- 评估独立“活动”入口，复用现有活动页面；移动端避免直接增加拥挤的底部导航。
- 建议主要分区：发现活动、感兴趣、我的活动。我的活动区分已报名、待审核、我发起、历史。
- “感兴趣”是收藏，不代表报名，不占名额；可取消，需持久化并与报名状态并列展示。
- 发现活动区分可见性与报名资格，不能泄露未公开活动或绕过星系成员权限。
- 动态可选关联星系或活动；选择活动时自动确定所属星系，服务器校验权限及关联一致性。
- 关联卡片支持进入星系／活动；活动详情承接讨论和活动回顾。
- 现有 Post 与 CommunityPost 是独立模型，ADR 0001 已明确此点。是否调整模型、跨页面展示与互动归属需评估并记录新决策，不能无意合并或复制。
- 活动验收：发现 → 感兴趣／取消收藏 → 加入星系／审批 → 报名／审批 → 取消或活动结束 → 回顾。
- 动态验收：发布／媒体上传 → 可选关联 → 展示与权限 → 点赞／评论 → 各入口跳转 → 编辑／删除同步。
- 覆盖作者、普通成员、非成员、待审核成员、组织者、管理员；检查重复提交、容量、过期／取消活动和失效关联。

## 2. 消息与提示

- 梳理私信、光束、系统通知、互动通知的真实数据来源、入口及权限，明确哪些仍为演示数据。
- 区分对话消息与系统／互动通知，统一未读数量及已读状态；沿用此前避免入口冗余的要求。
- 验收：触发动作 → 收件人收到消息／通知 → 未读数更新 → 点击进入正确对话／内容 → 标记已读 → 各入口与刷新后同步。
- 检查头像菜单、我的空间、消息列表、通知列表的跳转和状态一致性。
- 覆盖回复、删除／失效内容、分页／加载更多、空状态、请求失败、重复触发、跨账号隔离、屏蔽后的行为。
- 通知正文使用收件人语言；内容权限由目标接口再次校验，不能仅凭通知链接访问。

## 3. 发现星球、光束、轨道与关注

- 评估“发现星球”独立栏目及与首页／共鸣／现有 discover 页的职责；此项尚未决定，不新增重复页面。
- 验收主线：发现／搜索／筛选 → 星球详情 → 发送光束、保存到轨道、关注 → 我的空间／轨道／消息中查看结果。
- 光束：真实发送和接收、状态反馈、收件通知、能否回复／进入对话、重复点击与失败重试；不能只播放动画或使用模拟消息。
- 轨道：保存／移除、持久化、各入口同步、列表及详情跳转、重复保存幂等。
- 关注：关注／取消、关注关系与列表同步、通知、重复操作幂等；与“保存到轨道”明确区分。
- 检查自身星球、私密／屏蔽／删除／停用星球、未登录用户、重复请求及权限变更。
- 首页、发现、共鸣、轨道、关注、消息中的星球均使用相同定制头像及可见性规则。

## 建议执行顺序（待后续实施）

1. 核查消息、提示与光束是否连接真实后端，以及接收／已读闭环。
2. 验证发现星球 → 光束／轨道／关注的完整链路，再确定发现入口布局。
3. 完善活动收藏与独立入口，以及动态可选关联。
4. 部署后进行真实多账号端到端验收，逐项记录通过／失败；局部测试不替代完整验收。
