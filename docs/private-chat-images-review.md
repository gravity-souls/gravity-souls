# 私聊图片发布与验收

本轮完成：选择静态 JPEG／PNG／WebP → 本地预览／移除 → 明确发送 → 私密上传 →
绑定消息 → 未读与站内通知 → 两端展示／大图 → 已读；失败保留选择，上传成功而
发送响应丢失时复用附件和发送键，不创建第二条消息或通知。没有附言、任意文件、
语音、视频、系统推送或端到端加密。

## 权限与文件处理

仅真实会话参与者可操作，新增上传／发送要求双方账号有效、未双向屏蔽。未发送
附件只有上传者能读取；发送后允许双方鉴权读取。删除账号沿用匿名化历史规则，
有效对方可以读取旧图片，已删除查看者不能读取，新发送被拒绝。个人空间可见性
变化不自动撤销已经建立的私聊；屏蔽会撤销当前读取权限。

二进制请求最多 3 MiB；客户端不压缩，超过限制需先缩小图片再选择。服务端检查
真实文件格式、静态帧和 1600 万像素上限，旋转、缩放至最长边 2048、去 EXIF 后
重编码 WebP。原始文件、名称、EXIF 不存储。解码尝试限每小时 60 次，新预留限
每小时 20 个；发送沿用每小时 60 条的消息桶。幂等确认不重复扣新消息额度。

图片存储在私密对象存储，URL 从不返回客户端或导出。聊天使用鉴权 API 字节响应，
不走公开 Blob、Next 图片优化或公开缓存。所有字节／权限响应 private/no-store。
只加载视口附近的图片，滚离后释放图片字节。打开后每 10 秒及恢复前台通过 HEAD
复查权限，失败关闭大图并撤销本地 Object URL；
已经收到的信息无法从接收者记忆或其另存副本中撤回。这不是实时权限推送。

每个上传 UUID 只有一个写入者和不可复用的对象键。未完成尝试两分钟内返回处理中，
之后将其标记为待清理，要求新 UUID；成功上传在未过期时可重试复用。未发送附件
一小时过期；取消／账号删除先标记禁止发送。清理与发送使用同一附件行锁，已绑定
消息不可清理。正在写入的未就绪附件即使取消也等待一小时，超过函数／存储写入
期限后再删除。存储删除成功后才删除元数据；失败保留登记，下次重试。

## 部署配置

1. 创建 **private** Vercel Blob store，将其专用 token 配置为 `CHAT_PRIVATE_BLOB_TOKEN`。
   不复用动态／头像的 `BLOB_READ_WRITE_TOKEN`；无私密配置时上传返回 503。
   使用当前安装的 `@vercel/blob` 2.3.3 private put/get；没有在本轮创建或写入线上存储。
2. 配置随机 `CRON_SECRET`。`vercel.json` 设定每日 UTC 03:00 请求清理接口（Hobby 可能在该小时内触发），要求正确
   Bearer secret。每次最多扫描 100 条；失败保留记录，积压需要运维再触发清理。
   未发送对象可能保留到下一次成功扫除；已发送图片不增加自动保留期限。
3. 正常发布执行新增迁移 `20261005030000_add_private_chat_images`。新增附件表、
   nullable 唯一外键及形状 CHECK，无旧迁移修改、回填或数据删除。发布前只读检查
   `SELECT count(*) FROM direct_message WHERE type = 'image';`；旧代码没有图片发送，
   但若曾外部导入这种类型，先检查其数据，不能盲目迁移或覆盖。
4. 应用／客户端一起更新。回退时保留新表／列和附件，不执行破坏性 down migration；
   旧客户端会把新图片消息显示为空文本，不可当作兼容体验。

本地测试可明确设置绝对路径 `CHAT_IMAGE_LOCAL_DIR`，必须在 public 之外；production
完全禁用这种回退。测试不读取线上凭据、不连接生产数据库、不执行线上迁移。
